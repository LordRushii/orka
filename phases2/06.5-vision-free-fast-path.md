# Phase 6.5 — Vision-free fast path

## Goal

Most rounds — navigate, click a named control, type into a named field, select — are decidable from
the accessibility snapshot alone. On those rounds, **skip the screenshot entirely**, which removes the
whole ~6.3 s pixel scan (OCR + face) for that round. This is the single biggest latency win and it is
what makes the multi-round loop from Phase 6 affordable. Vision rounds (explain-this-page, or a target
that can't be resolved from the snapshot) still capture and scan exactly as today.

## Current state

- `sanitize()` always requires a screenshot and always runs OCR + face
  (`sanitize.ts` `isValidScreenshot`, `runOcrDetection`, `runFaceDetection`).
- `SanitizedObservation.screenshot` is required in `packages/contracts/src/observation.ts`.
- Depends on Phase 6 (the loop) being in place.

## Tasks

1. `packages/contracts/src/observation.ts`: make `SanitizedObservation.screenshot` **optional**. A
   snapshot-only observation is valid with no screenshot. `PlanRequest`/`PlanResponse` shape is
   otherwise unchanged; assert the gateway/adapters treat "no image" as a text-only prompt.
2. `packages/privacy-engine/src/sanitize.ts`: when `input.screenshot` is absent, run DOM detectors +
   `redactAccessibilitySnapshot` only, and skip `runOcrDetection`/`runFaceDetection`. Gate on
   `screenshot === undefined`, never on a caller-set flag. Fail-closed is unchanged.
3. `apps/extension/entrypoints/background.ts`: decide per round whether vision is required. Default
   rounds capture **snapshot only** (no `captureVisibleTab`). Capture a screenshot only when the round
   is vision-required: an explicit "look at / explain the page" turn, a `done`/`ask_user` needing visual
   grounding, or a step whose target could not be resolved from the snapshot (fall back to a vision
   round and re-plan). If a vision-required capture fails, fail closed (`CAPTURE_FAILED`) — never
   silently downgrade to text-only.

## Docs to update in the same commit

`docs/SECURITY-PRIVACY.md`, `docs/ARCHITECTURE.md`, `docs/PRD.md`: the observation is now "a redacted
snapshot, plus a redacted screenshot on vision rounds" (was "always a redacted screenshot + snapshot").
State explicitly that redaction is not weakened — a vision-free round produces no screenshot pixels at
all, and DOM text still passes the deterministic detectors before anything leaves the extension.

## Acceptance

- A task that only clicks/types by accessible name completes with **zero** OCR and face invocations
  (assert the recognizer/detector mocks were never called) and its observation carries no screenshot.
- An "explain this page" task still captures and scans.
- Fail-closed test: a vision-required round with a failed capture fails, never proceeds text-only.
- Validation gate green; push.
